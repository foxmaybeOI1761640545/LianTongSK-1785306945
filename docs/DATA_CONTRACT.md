# Dashboard 数据契约与指标口径

> 当前真实样本版的大屏口径以 [大屏真实数据接入与指标溯源](REAL_DATA_METRIC_PROVENANCE.md) 为准。当前契约服务于“用户体验行为信号 + 公司价值机会”展示，不包含双边对账和结算金额字段。

## 设计目标

页面组件不感知数据来自 Mock、DataEase 还是业务 API。任意适配器都必须返回同一 Dashboard View Model，确保更换数据源时不重写页面。

```js
await dashboardDataAdapter.loadDashboardData({
  range: '7',
  segment: 'ALL',
})
```

## 核心字段

| 字段 | 类型 | 说明 |
|---|---:|---|
| `date` | `YYYY-MM-DD` | 统计日期 |
| `activeUsers` | integer | 当日或当前周期去重活跃用户数 |
| `recordCount` | integer | 当前样本记录数 |
| `totalBytes` | integer | 漫游流量，底层统一使用 bytes |
| `segment` | enum | `ALL`、`HIGH_USAGE`、`RECALL`、`GROWTH`、`ENTERPRISE` |
| `experienceSignals` | array | 月度多标签行为候选及人数 |
| `headTrafficShare` | number | Top 10% 用户的流量贡献比例 |
| `coverageNote` | string | 单侧样本覆盖边界说明 |

## 指标公式

```text
人均漫游流量 = 漫游总流量 ÷ 活跃用户数
高用量重点用户数 = 当前周期用户数 × 10%，向上取整
头部流量贡献 = Top 10% 用户流量 ÷ 当前周期漫游总流量
```

样本覆盖由“用户归属地 + 实际上网地”判定；当前只展示广东侧样本用户访问香港网络。缺少的对侧样本必须表达为“未提供”，不得输出为真实业务量 `0`。

## 行为候选规则

当前大屏使用以下非互斥候选标签：

- 高用量重点用户：当前周期按用户总流量排序的 Top 10%；
- 低活跃召回候选：来自月度报告规则，需结合后续活跃与触达数据验证；
- 价值提升候选：来自月度报告规则，需结合套餐与转化数据验证；
- 企业场景特征候选：仅代表行为相似，不能确认企业身份。

正式接入时阈值必须配置化，并由业务团队结合套餐、收入、身份、触达和满意度数据确认。

## 公开演示要求

- 手机号码只保存脱敏形式；
- KPI、趋势和分布必须从同一批源数据聚合；
- 页面顶部必须展示静态样本、记录数、用户数、单侧覆盖范围与行为标签免责声明；
- 禁止展示无资费支撑的结算金额、伪造反向业务量、排名生成的风险分或生产收益；
- 行为候选之间可重叠，禁止将人数相加后解释为用户总数。
